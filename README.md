# NEXUS Network

Кроссплатформенный стартовый проект: Windows и Android, режимы Server и Client, GitHub private registry для обнаружения сервера.

## Что реализовано

- GUI на Kivy для Windows и Android.
- Сервер WebSocket и клиент WebSocket.
- Публикация записи сервера в приватный GitHub-репозиторий через Contents API.
- Heartbeat сервера каждые 5 минут.
- Срок действия записи 15 минут.
- Клиент читает реестр сразу при запуске и повторяет поиск каждые 5 минут после неудачного подключения/отключения.
- Клиенты авторизуются отдельным общим ключом NEXUS; этот ключ не публикуется в GitHub.
- При штатной остановке сервер пытается удалить свою запись; при аварийной остановке запись истекает по expires_at.

## Важно: это ранняя версия

Транспорт в этой сборке использует `ws://` и предназначен только для тестирования в доверенной сети. Перед использованием через публичный интернет необходимо включить TLS и перейти на `wss://`. Не открывайте порт в интернет в текущем виде.

Android foreground service ещё не включён: Android может приостанавливать приложение в фоне. Для длительной работы сервера потребуется отдельный foreground service с постоянным уведомлением.

## GitHub Registry

Создайте отдельный **приватный** репозиторий, например `NEXUS-Registry`.

1. Для сервера создайте Fine-grained PAT только для этого репозитория с разрешением **Contents: Read and write**.
2. Для клиента создайте отдельный Fine-grained PAT только для этого репозитория с разрешением **Contents: Read-only**.
3. В приложении введите owner, имя приватного репозитория и соответствующий токен.
4. Создайте один длинный общий ключ NEXUS (минимум 12 символов) и введите его на сервере и клиентах. Не публикуйте его в registry.
5. В поле публичного адреса сервера укажите публичный IP/DNS или VPN-адрес, достижимый клиентами. Не указывайте 0.0.0.0 или 127.0.0.1.

GitHub-токены не нужно коммитить в репозиторий NEXUS и нельзя встраивать в APK. В этом MVP они вводятся вручную в интерфейсе и остаются в памяти процесса.

## Windows

Рекомендуется Python 3.11:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python main.py
```

Если PowerShell блокирует активацию, запускайте напрямую:
`\.venv\Scripts\python.exe -m pip install -r requirements.txt`, затем `\.venv\Scripts\python.exe main.py`.

## Android APK

Сборку выполняйте на Linux/Ubuntu или WSL с Android SDK/NDK:

```bash
python3 -m pip install --user buildozer
buildozer android debug
```

APK будет в каталоге `bin/`.

## Первый тест

1. Создайте приватный репозиторий NEXUS-Registry и два PAT (RW для сервера, Read для клиента).
2. Запустите сервер, задайте внешний адрес и порт 8765.
3. Разрешите входящий TCP-порт в брандмауэре/роутере или используйте VPN-сеть.
4. Запустите клиент с read-only PAT и тем же общим ключом NEXUS.
5. Для теста сообщений откройте два клиента, подключённых к одному серверу.

## Ограничения первой версии

- Клиент выбирает первый активный сервер из реестра, если Server ID не указан.
- GitHub используется только для обнаружения сервера; сообщения идут напрямую по WebSocket.
- Одновременная публикация несколькими серверами в один JSON-файл может вызвать конфликт Contents API. Для нескольких серверов нужен отдельный файл на каждый Server ID либо серверный координатор.
- Для настоящего публичного релиза нужны TLS, безопасное хранение токенов, Android foreground service и тестирование на устройствах.
